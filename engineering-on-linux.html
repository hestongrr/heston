Engineering on Ubuntu Linux

I do geotechnical and civil engineering on a Linux desktop every day — site characterization, soil classification, seepage and slope analysis, 3-D site models, and applied AI over project documents. This page is the honest map of what runs on Ubuntu, what it costs to set up, and what — still, in 2026 — stubbornly does not. No hype.

Why run an engineering workstation on Linux?

The serious engineering suites (gINT, Slide, LPile, and friends) are Windows-first, and that's a real constraint, not a marketing line — I keep a Windows box for the few things that won't leave it. But the other 90% of the discipline — the maps, the data, the computations, the figures, the writing, the AI — runs better on Linux: no licensing games, a shell and a package manager for a real automation loop, Python as a first-class citizen, and an open AI stack that keeps client data on your machine instead of someone else's server.

This is the stack I actually run. Every piece is one I've used on paid work, and every command below is one that lives in my own setup.

1 · The baseline

Start with Ubuntu 24.04 LTS and the GPU driver

Almost everything below is a package away. Two non-negotiables: the NVIDIA driver (for the 3-D and local-AI workloads), and Flatpak for the apps that aren't in the apt repos.

  1. Install Ubuntu 24.04 LTS — the 5-year LTS support cycle beats chasing a release calendar mid-project.
  2. Install the proprietary NVIDIA driver — sudo ubuntu-drivers install. Needed for Blender, Godot, and running local LLMs at usable speed on the GPU.
  3. Enable Flatpak — sudo apt install flatpak and the Flathub remote. This is how I get current versions of the GUI engineering apps without waiting on distro repos.
  4. Install Python tooling — sudo apt install python3 python3-pip git, then keep project environments isolated (venv or micromamba) so a geotech package upgrade can't quietly break a working script.
A headless machine that only runs services doesn't need the desktop at all — I keep a separate lightweight server (Docker + K3s) that runs the web tools and AI services, and the desktop workstation just talks to it.

2 · Mapping & site data

QGIS is the workhorse

Site maps, boring locations, geologic mapping, and deliverables as GeoJSON that engineering and land-development teams can actually consume. This is the closest thing on this list to a drop-in replacement for the Windows GIS default.

QGIS

GIS & site mapping

Borehole and test-pit locations, parcel and right-of-way boundaries, geologic units, and publishing site maps to GeoJSON/GPKG. The projection handling and print-layout system are genuinely production-grade.

sudo apt install qgis
GeoJSON / GPKG

Portable project data

Keep engineering site data as GeoJSON next to the report so a client or reviewer can drop it straight into their own GIS. Versionable in git like any other project deliverable.

3 · Computation & analysis

Spreadsheets for the record, Python for the analysis

Two layers, deliberately separated: LibreOffice for the hand-checked, reviewable arithmetic a client expects to see, and Python for the computations that a spreadsheet shouldn't be trusted with.

LibreOffice Calc

Reviewable arithmetic

Bearing capacity, settlement, unit weights, QC logs — the tabulated work that has to be auditable line by line. Opens native .xlsx without round-trip corruption.

sudo apt install libreoffice-calc
Python + NumPy/SciPy

Real computation

Finite-difference wave propagation (my cavity-detection work is pure NumPy), flow-net solutions, classification decision trees, and any solver a spreadsheet would turn into an unreadable mess.

pip install numpy scipy
Matplotlib

Figures that don't lie

Pressure diagrams, grading curves, N-value plots — generated from the same numbers the analysis used, so the figure can't disagree with the computation.

pip install matplotlib

4 · Drawings & figures

Vector figures, raster edits, and PDF delivery

Inkscape

Vector technical figures

Cross-sections, stratigraphy callouts, diagram callouts — SVG, which also means the figures can be generated from code and stay consistent across a report.

flatpak install flathub org.inkscape.Inkscape
GIMP

Raster cleanup

Scan touch-up, site-photo annotation, and anything that arrives as a raster that needs to leave as one.

sudo apt install gimp
LibreOffice Writer

Reports & PDF delivery

The report body, exported to PDF for submittal. Same reviewable-arithmetic rule as Calc: tables and text stay in one auditable document.

sudo apt install libreoffice-writer

5 · 3-D site models

Terrain, stratigraphy, and build sequences

Site models built from real USGS elevation data — the kind that make a design review actually understand the ground before anyone moves dirt.

Blender

3-D site & subsurface modeling

Terrain surfaces from elevation grids, cut-face stratigraphy, grading pads, and rendered build-sequence frames. Also the mesh side of the pipeline that feeds the browser tools.

sudo apt install blender
Godot

Interactive 3-D model viewers

Walkable viewers for site and subsurface models — a .glb/.gltf drop-in viewer that lets reviewers explore a model instead of staring at a static render.

flatpak install flathub org.godotengine.Godot
FFmpeg

Render sequences to video

Turns a frame-by-frame build sequence (excavation, fill, foundation) into a deliverable the client can actually sit through.

sudo apt install ffmpeg

6 · Applied AI for engineering

Local models, because client data shouldn't leave the machine

The engineering-safe way to use AI: models that run on your own GPU, over your own documents, with the verification habits that keep a wrong answer off a drawing. See what AI is actually good at in engineering.

Ollama

Local LLMs

Report drafting, spec review, and memo Q&A with the model running on the workstation GPU — no project data sent anywhere. This is the guardrail, not the selling point.

curl -fsSL https://ollama.com/install.sh | sh
Local RAG over project docs

Answers grounded in your files

Retrieve from your own geotech reports, specs, and notes before the model answers, so the response cites the source and you can verify it — the only way AI belongs in the workflow at all.

TRELLIS image→3-D

Site photos to 3-D

Turns a photograph into a textured mesh for quick conceptual models of an exposed face or borrow-pit condition — draft-grade geometry, not survey-grade, and labeled as such.

The rule that keeps this safe: AI drafts, the engineer verifies. Every number a model produces gets checked against a hand calculation or an independent method before it reaches anything with a project number on it.

7 · The honest limits

What still won't run on Linux

Being straight about this is the whole point of the page. If a specific proprietary geotech suite is required by your client, Linux is not the hill to die on.

SoftwareStatus on LinuxWorkaround
gINT (geotechnical data management)No native version Windows box / VM with the data files in git-versioned CSV
Slide / LPile (slope & pile analysis)Windows-only Windows box, or run the hand calculations in Python for verification
MicroStation / Civil 3DWindows-only Deliverables still go out via Windows; geometry moves as DXF/IFC and survives the trip
Bluebeam (PDF markup)Windows-only PDF mark-up on Linux with web-based tools; fine for review cycles
The split I actually live by: anything that must run on Windows runs on Windows, and everything else runs on Ubuntu with a proper automation loop. The boundary is explicit, documented, and never a surprise at deadline time.

Every tool on this site runs in the browser.

Because the deliverable should never depend on your OS. The calculators and simulators on this site — soil classification, slope stability, cavity detection — run entirely in the browser, on any machine that ships one.
