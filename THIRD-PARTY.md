# Third-party libraries

The tools on this site are hand-written, but they stand on open-source work.
Everything redistributed from `lib/` is listed here with its author, version,
license, and upstream source. Nothing here has been modified — each library is
vendored as published.

For the licensing of *this* repository's own code, see [`LICENSING.md`](LICENSING.md).

## three.js — r128

3D rendering engine. Every 3D tool on the site is built on it.

- **Authors:** Three.js Authors (project lead: Ricardo Cabello / mrdoob)
- **License:** MIT
- **Upstream:** https://github.com/mrdoob/three.js
- **Vendored as:** `lib/three.min.js` (license header retained in the file),
  full licence text in `lib/three.LICENSE`

The minified bundle carries only a copyright line and an SPDX tag. MIT requires
the *full* permission notice to accompany copies, so the complete licence text
is included separately. It covers `lib/OrbitControls.js` too — same project,
same licence.

Used by: `sand-3d`, `redrock-3d`, `nuke-gauge`, `grade-it`, `ifc-viewer`,
`subdivision-build-sequence`, `rocks-demo`, `rocks-3d`.

viewer. From `examples/js/loaders/GLTFLoader.js`.

- **Authors:** Three.js Authors
- **License:** MIT
- **Upstream:** https://github.com/mrdoob/three.js
- **Vendored as:** `lib/GLTFLoader.js`

Same project and licence as `three.min.js` / `OrbitControls.js`, covered by
`lib/three.LICENSE`. Unmodified from the r128 examples build.

Used by: `rocks-3d`.

## web-ifc

IFC (Industry Foundation Classes) parser compiled to WebAssembly. Powers the
BIM viewer's ability to read real `.ifc` building models in the browser with no
proprietary software.

- **Authors:** That Open Company (ThatOpen) and contributors
- **License:** **Mozilla Public License 2.0** — see `lib/web-ifc/LICENSE`
- **Upstream:** https://github.com/ThatOpen/engine_web-ifc
- **Vendored as:** `lib/web-ifc/web-ifc-api-iife.js` and `lib/web-ifc/web-ifc.wasm`

MPL-2.0 is a file-level copyleft licence, unlike the MIT licences above. The
compiled bundle and WASM are redistributed **unmodified**; the full licence text
is included alongside them, and the source is available at the upstream link.
If any web-ifc file is ever modified, that modification must itself be released
under MPL-2.0.

Used by: `ifc-viewer`.

deliverable will name its author, client, and job number right there.

## Rock scans (`rocks3d/`)

Photogrammetry scans of real rock hand samples, used by the Rocks 3D specimen
viewer (`rocks-3d.html`). Both are **USGS-authored** products. USGS-authored or
produced data and information are in the U.S. public domain (USGS "Copyrights
and Credits" policy), so commercial use is permitted; credit to USGS is
requested and is given on the viewer page and below.

| File | Specimen | Origin | Rights |
|---|---|---|---|
| `chromite.glb` | Podiform chromite (hand sample) | USGS 3D Science Catalog (ScienceBase item `64c0178ed34e70357a323216`), scanned by Lucas Evart, USGS GMEG Science Center | Public domain |
| `skarn.glb` | Garnet-quartz-scheelite skarn (hand sample) | USGS 3D Science Catalog (ScienceBase item `64c17c1cd34e70357a329de4`), scanned by Lucas Evart, USGS GMEG Science Center | Public domain |

Both files were **modified** for web delivery — meshes decimated and textures
re-encoded to 2048 px JPEG in Blender — which is permitted because USGS works are
public domain. Full-resolution originals are retained off-site.

**Rule for adding scans:** USGS / Smithsonian 3D-catalog items are public domain
and safe to publish. Sketchfab models are **NOT** automatically usable: check the
per-model license badge before downloading. CC-0 and CC-BY (commercial use with
attribution) are fine; anything with **NC** (non-commercial — `by-nc`,
`by-nc-sa`, `by-nc-nd`) or **ND** (no derivatives) must not be published on this
commercial portfolio site. Verified example to avoid: "Geological Rock Sample"
by Ghasan (Sketchfab uid `2aa45f0f3c1345249dc0ce1828798385`) is `by-nc-sa`.

## Considered and not used

Recorded so the reasoning isn't lost, and so nothing here is mistaken for a dependency:

- **[N8AO](https://github.com/N8python/n8ao)** — the reference screen-space AO
  implementation for three.js. Not adopted: it requires three.js r161+, ES
  modules, and the `postprocessing` package, while this site pins r128 with
  classic `<script>` tags. Sand3D uses a hand-written horizon-based ambient
  occlusion computed off the simulation's own heightmap instead, which needs no
  post-processing pipeline.
- **three.js bundled HBAO example** — same blocker (needs a much newer three.js).
  Worth revisiting if the site ever migrates to ESM.
- **`three-instanced-mesh` wrappers** ([lume](https://github.com/lume/three-instanced-mesh),
  [pailhead](https://github.com/pailhead/three-instanced-mesh)) — these predate
  `THREE.InstancedMesh` landing in three.js core, which is what the tools use.
