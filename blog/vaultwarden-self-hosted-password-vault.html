Vaultwarden: Your Own Password Vault, Bitwarden-Compatible

August 2, 2026 · Heston Norcott, E.I.

Use a password manager. That part isn't a debate — unique passwords for every site, generated and stored, is the single highest-leverage security habit there is. The question is where the vault lives.

A hosted vault is a honeypot: every credential you own, sitting on a server you don't control, behind the login of whatever company runs it. The alternative I run is Vaultwarden — a Bitwarden-compatible vault server so light it runs on one small box, where every secret stays on my hardware and only my tailnet can reach it.

What Vaultwarden Is

Vaultwarden is a community server that speaks the Bitwarden protocol. That means it drops into the same client apps you already know — the Bitwarden browser extension, desktop app, and mobile apps — all pointed at your own server instead of the company's cloud. The clients stay familiar; only the server is yours.

Run It Like Any Container

Following the Docker pattern, the whole vault is one compose file:

services:
  vaultwarden:
    image: vaultwarden/server:latest
    volumes:
      - ./data:/data              # the vault database lives here
    environment:
      - ADMIN_TOKEN=<long random token>
    ports:
      - "8080:80"
docker compose up -d

That's it — a working Bitwarden-compatible server. The ADMIN_TOKEN unlocks the admin panel, where you manage invitations and see what's on the server.

Don't Put It on the Internet

Here's the whole point: your vault should be reachable only by you. No port forwarding, no domain, no public exposure — reach it over your private tailnet, exactly like the rest of your homelab. A password vault nobody can find is a password vault that's safe.

# point the Bitwarden client at your tailnet address, e.g.
# https://vaultwarden.your-tailnet:8080

Backups Are the Second Half

A self-hosted vault is a responsibility: lose the data folder and you've lost every credential in it. So the backup is part of the setup — the vault data folder goes into the same backup routine as everything else on the box, on a schedule, off the server. The day you rebuild the host, the vault comes back with a git clone plus a docker compose up -d and a restored data folder.

The Honest Trade-Off

Self-hosting a vault trades a vendor's convenience for your control — and it costs you something real: you're now on call for it. Updates, backups, availability — that's you. The reward is that the most sensitive database you own is a file on a disk you hold, behind a network only you can enter. For engineering work, where client data and credentials shouldn't touch a third party's logs, that trade has been worth it every day.
