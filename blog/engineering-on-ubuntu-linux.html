I Run My Engineering Work on Ubuntu Linux — Here's How

August 2, 2026 · Heston Norcott, E.I.

People assume a geotechnical engineer's desktop has to be Windows. CAD, gINT, slope software, Bluebeam — that's the ecosystem the discipline grew up on, and nobody's pretending it doesn't exist. But I do the other 90% of the work on Ubuntu, and I've stopped treating that as a quirk and started treating it as an advantage.

The honest version: some proprietary geotech software still won't leave Windows, so I keep a Windows machine for those specific things. Everything else — the maps, the data, the computation, the figures, the writing, the AI — lives on Linux, where I have a shell, a package manager, and a Python that actually belongs to the machine.

The Stack

  • QGIS for site mapping — boring locations, geologic units, parcels, and deliverables as GeoJSON that a client's GIS can read without conversion ceremonies. This one is a genuine drop-in replacement.
  • LibreOffice Calc for the reviewable arithmetic — bearing capacity, settlement, unit weights — the tabulated work that has to be audited line by line. It opens native .xlsx without mangling it.
  • Python with NumPy and SciPy for the computation a spreadsheet shouldn't be trusted with — including my master's-thesis finite-difference wave propagation work, which is pure NumPy.
  • Inkscape and GIMP for vector figures and raster cleanup. My technical figures are generated from code, so a figure can't disagree with the calculation it came from.
  • Blender, Godot, and FFmpeg for 3-D site models — terrain from real USGS elevation, stratigraphy in the cut faces, and rendered build sequences delivered as video.
  • Local AI (Ollama + RAG) for report drafting and spec review, running on my own GPU. The reason that matters: client data stays on the machine. No project number is ever sent to a third-party server.

What Still Runs on Windows

Being straight about this is the whole point. gINT, Slide, LPile, Civil 3D, MicroStation, Bluebeam — no native Linux versions, and I don't pretend otherwise. The boundary is explicit and documented: anything that must run on Windows runs on Windows, and everything else runs on Ubuntu with a proper automation loop. It's never a surprise at deadline time.

Why This Beats The Spreadsheet-Only Workflow

On Windows, my tools were islands. The boring log lived in one program, the settlement calc in another, and getting a number from one to the other meant copy-paste. On Linux, they're all reachable from one shell — I can read field data, run a classification, generate the log, and drop the result into a report without re-entering anything by hand.

The difference isn't the operating system. It's the automation loop that Linux makes trivial, and that a desktop with no shell never offered.
