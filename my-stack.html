My Stack: The Tools I Actually Run

Everything on this site — the engineering, the 3-D models, the maps, the narration, the analytics — runs on a stack I own end to end: one Linux box, open tooling, and a browser for delivery. This page is the honest map: what each piece does, why it earns its place, and the exact command to set it up yourself.

The one rule: run as much as possible, own as much as possible

My work is geotechnical engineering, so the serious Windows-only suites (gINT, Slide, Civil 3D) still exist in my life. But the other 90% of the discipline runs better on open tooling — and it has one huge advantage: the whole pipeline is inspectable, scriptable, and reproducible. No licensing games, no black-box solver, no deadline surprise.

Two delivery principles run through everything: client data stays on my hardware (local AI, not someone else's API), and deliverables run in the browser (so a reviewer never needs my OS to open my work).

1 · The platform

One Linux machine does the work

A single Ubuntu box is both my workstation and my server — desktop when I need a screen, headless services when I don't. One machine to patch, one machine to back up, and a shell to automate the whole thing.

Ubuntu 24.04 LTS

Workstation + server in one

Five-year LTS support, the NVIDIA driver a package away, and Python as a first-class citizen. The desktop talks to the same services the house uses, so nothing is ever "the other box".

sudo apt update && sudo apt upgrade
Docker + Compose

Services, isolated

Every self-hosted service runs as a container with its config in one compose file. Restart a service without touching the host; rebuild one without breaking the rest.

docker compose up -d
systemd

The scheduler and babysitter

Timers run the daily jobs — analytics, backups, monitoring — on schedule, and service units keep the web tools alive across reboots. No cron hacks, no "it stopped overnight".

systemctl --user list-timers
Git

Every project is versioned

The site, the scripts, the engineering data — all in git, so a deliverable can be diffed, rolled back, and reproduced. This site ships straight from a git push.

git push origin main

2 · Engineering

The dirt stack

The same data flows through GIS, Python, and a spreadsheet — each in the job it's actually good at. The figure is always generated from the same numbers the analysis used, so it can't disagree with the computation.

QGIS

GIS & site mapping

Borehole locations, parcel and ROW boundaries, geologic units, deliverables as GeoJSON that a land-development team can drop straight into their own GIS.

sudo apt install qgis
Python + NumPy / SciPy / Pandas

Real computation

Finite-difference wave propagation, flow-net solutions, classification logic, and the data plumbing that joins a lab sheet to a report. The engine behind this site's calculators.

python3 -m venv .venv && ./.venv/bin/pip install numpy scipy pandas
GeoPandas / Shapely / Pyproj

Spatial data that stays spatial

Reproject, buffer, and clip site data in code — no hand-tracing in a GUI, no coordinate drift between the map and the model.

pip install geopandas shapely pyproj rasterio
LibreOffice Calc

Reviewable arithmetic

Bearing capacity, settlement, QC logs — the tabulated work a client expects to audit line by line. Opens native .xlsx without round-trip corruption.

sudo apt install libreoffice-calc
Matplotlib

Figures that don't lie

Pressure diagrams, grading curves, N-value plots — generated from the computation's output, so the drawing is a claim about the data, not a sketch of it.

pip install matplotlib
FreeCAD + Gmsh

Geometry when it's not a map

Parametric 3-D site geometry and mesh generation for the models that turn into figures, IFC, or 3-D scenes.

sudo apt install freecad gmsh

3 · The web

Deliverables in the browser

This site is a static site served by a tiny Python service. The engineering tools are client-side — pure HTML, CSS, and JavaScript — so a reviewer can open the same calculator I used, on any machine that ships a browser.

HTML + CSS + vanilla JS

No framework tax

Static pages, hand-written, versioned in git. Fast, auditable, and it has a ten-year lifespan instead of a framework's release cadence.

python3 -m http.server 8801
three.js

3-D in the browser

Subdivision build sequences, site models, and drill-rig animation — real-time 3-D that needs no install and no GPU license.

npm install three
uvicorn (Python backend)

The tiny serving layer

A minimal ASGI app serves the site and the API. Logs rotate, timers refresh the analytics, and it reads straight from disk — a push to git is a deploy.

uvicorn backend:app --port 7700
GoAccess

Self-hosted analytics

Real traffic stats, generated from my own logs on my own box — no third-party trackers feeding a business I don't control.

goaccess access.log -o report.html --log-format=COMBINED
cloudflared

Quick tunnels for previews

One command exposes a local page to the internet on a throwaway URL — how a client gets a live preview of their site before it ever ships.

cloudflared tunnel --url http://localhost:8801

4 · The homelab

Ops you can read like a recipe

One home server runs the self-hosted services. Because it's my own hardware, I control the ports, the logs, and the data — and I can rebuild any piece of it from a compose file.

Docker Compose

Declared, not administered

Each service's whole life is in a compose.yaml — image, volumes, ports, env. A fresh box is a git clone plus docker compose up away.

docker compose config --services
Tailscale

A private network that behaves

Zero-config VPN between my machines — game servers, SSH, and admin panels reachable only by my tailnet, no port-forwarding to the internet.

sudo tailscale up
Prometheus + Grafana + Loki

Metrics and logs in one place

What the services are doing, in graphs; what they said, in logs. A dead node or a pegged disk shows up before a user notices.

curl localhost:9100/metrics | head
Uptime-Kuma

The dead-man's switch

Pings every public and internal service, and alerts when something stops answering. Cheap insurance for a one-person ops team.

The privacy line: the homelab is deliberately private — internal addresses, service names, and credentials never make it to this page. The pattern is open; the specifics stay behind the tailnet.

5 · Media & AI

Local generation, no uploads

The 3-D videos and narration on this site are produced on my hardware: the scenes render in a headless browser, the voice is synthesized locally, and the AI that reads project documents never leaves my box.

ffmpeg

Every frame, composed

Captures the rendered scenes and assembles the final video — the same tool a studio uses, available as one package.

sudo apt install ffmpeg
edge-tts

Narration without a booth

Generates clean voiceover locally from text — a script becomes audio with no recording session, no upload, and complete control of pacing and rate.

pipx install edge-tts
Headless Chromium

A screen that never sleeps

Renders the 3-D scenes offscreen for capture — same engine a user would see, producing frames at full resolution without tying up a monitor.

Ollama (local LLMs)

AI on my own GPU

Project documents, site records, and engineering text get read by models running on my hardware — the work product stays with the client, never in a third party's logs.

ollama run llama3.2

6 · The honest boundary

What still runs on Windows

Open tooling doesn't cover everything in geotech yet. The boundary is explicit so it's never a surprise at deadline time.

SoftwareStatus on LinuxWorkaround
gINT (geotechnical data management)No native version Windows box / VM, with the data files in git-versioned CSV
Slide / LPile (slope & pile analysis)Windows-only Windows box, or hand calculations in Python for verification
MicroStation / Civil 3DWindows-only Deliverables via Windows; geometry moves as DXF/IFC and survives the trip
Bluebeam (PDF markup)Windows-only Web-based PDF markup for review cycles
The split I actually live by: anything that must run on Windows runs on Windows, and everything else runs on open tooling with a real automation loop. That's not a compromise — it's a designed boundary.
